## New in v3.8 &mdash; the charts are in the Word documents
- **A run can no longer report success for checks it did not run.** Pointing `CHROME` at a path that does not exist took the visual suite from 219 checks to 172 and it still printed "172 visual check(s) passed" and exited 0 &mdash; the forty-seven that vanished were every one that reads what the page actually produces in a browser rather than what its source says. The same absent binary emptied the Word layer of the mutation suite, which went on to print "Every check still has teeth". A missing `formulas` package did the same to the recalculation layer through a warning, and warnings never reached the exit code, so the most expensive question the harness asks &mdash; does every shipped workbook actually compute &mdash; answered itself *skipped* under the word PASSED, which is the default on a fresh clone. Each of these now fails and names what could not run. A skip you asked for (`--fast`, `--skip-browser`, `--skip-optional`) still exits 0, but the summary says NOT RUN and never folds those checks into the count that passed.
- **Chrome is looked for in more than one place.** A single hardcoded path made a machine with Chrome installed somewhere else indistinguishable from one with no Chrome at all. `$CHROME`, `$CHROME_PATH`, the usual macOS locations and `PATH` are all tried, and the failure message lists everywhere it looked.
- **The hand-patched workbooks' keys are derived too, and per sheet.** Theirs is a different shape &mdash; heading in column A, explanation beside it, sitting on the data sheet under "HOW TO USE THIS SHEET" &mdash; and it was written by a fixed list of cell addresses asserting all three colours, so it was right only for as long as nobody changed a sheet underneath it. Rows are rewritten in place, never inserted or deleted: the data starts two rows below and several hundred cell addresses point at it, so shifting a row to tidy a legend would move every one of them. A colour the sheet does not use empties its row and the rest close up above it.
- **`verify` now checks each sheet's key against that sheet.** A key headed "HOW TO USE THIS SHEET" answers for one sheet, and checking only the workbook total let a sheet with no worked example sit under a key promising one, because another tab's green cells covered it. Clearing a single key line on one sheet fails that sheet by name.
- **The calculator key reads like the rest of the pack now** rather than as two sentences of prose, so the same reconciliation owns it.
- **The colour key is now derived after the fills exist, not before.** The v3.7 fix ran at the end of each builder, which is one step too early &mdash; the polish pass that runs on the way out adds cells of its own, so the DOE matrix and the Gage R&amp;R study shipped using green cells their key never mentioned. In memory each reported two colours; the same workbook reloaded from disk reported three. The reconciliation moved into `polish_workbook`, where every fill exists, and the key itself now has one definition that `build_templates` imports rather than a second copy to drift from. All 22 workbooks match their sheets, both halves of the pack, and `verify` checks each one against the saved file &mdash; renaming a single key line in one workbook fails that workbook by name.
- **Fixed while doing it: inserting a row unmerged everything below it.** openpyxl moves cells but leaves merged ranges and row heights where they were, so adding two lines to the Gage R&amp;R key dropped four notes into column A, which is two characters wide &mdash; the longest wrapped to ninety-two lines.
- **The calculator workbook now carries the same colour key as the rest.** It explained its colours in prose &mdash; "change the YELLOW cells, everything else is a formula" &mdash; which is true, and is not the key the other twenty-one workbooks carry. A reader who has learnt to look for one would not have found it. The seven other hand-patched workbooks were measured at the same time and all seven already matched their sheets.

What was there instead was a table of shaded cells standing in for each chart &mdash; which is why the export kept measuring as working. The chart is rasterised to PNG on a canvas before the document is assembled and embedded as a real image part with its own relationship and content type, so the picture in the Word file is the picture in the workbook rather than an approximation of it. 43 of 43.

If any chart fails to rasterise the bars stay for all of them: a reader who loses the picture should not also lose the numbers. One of them was counting *all* cell shading, so it had quietly started measuring the colour-coding added in v3.6 rather than any chart at all.

## New in v3.7 &mdash; the swimlane map the tool library has always described
- **Every sheet's colour key now matches the sheet.** `LEGEND` explained yellow, blue and green on all of them, so the Kanban board and the Erlang staffing table opened by telling readers to look for green cells they do not have &mdash; on those two the seeded input values *are* the worked example, and they are yellow because that is where you type. - **New: `33-swimlane-process-map.xlsx`.** The tool library has carried a full Swimlane process map card since the beginning &mdash; when to use it, one lane per actor, mark every handoff, record the decision rule the agent actually uses &mdash; and there was no template behind it. Its two siblings in the same sentence both had one: value stream map and system-hop. This is the third.

## New in v3.5 &mdash; the pack says what its numbers mean, and the harness checks

- **Fixed: a benefit case that was arithmetically exact and causally impossible.** The worked project ran on `266,000 &times; 6.2 points &times; $6.80 &times; 0.85 = $95,324`, and every multiplication in it is correct. The chain is still nonsense, because the 6.2-point gap is measured on in-scope billing adjustments and the 266,000 is the whole billing queue. Adjustments are 11,592 of those 266,000 contacts and 1,646 of the queue's 37,772 reopens &mdash; 4.4% of each &mdash; so fixing *every* adjustment reopen in the year moves the queue rate from 14.2% to 13.58%. That is 0.62 points against a claimed 6.2: ten times the arithmetic maximum. What hid it is that the reopen rate is 14.2% on both populations, measured two different ways, so the figure reconciled everywhere anyone looked. The honest chain is `11,592 &times; 6.2 points = 719 &times; $38.60 = $27,753 &times; 0.85 = $23,590`, which does not clear the $50,000 floor Finance books against &mdash; and the pack now says so, in the charter, rather than quietly carrying a number that works. The unit cost moved with it: $6.80 is the cost to serve one contact and was never the price of a reopen. This is the ordinary way a benefit case dies, and the v1.0 chain is kept in the revision history instead of deleted, because recognising the shape of it is the lesson.
- **The metric dictionary now says what the numbers are.** NPS was defined as detractors subtracted from promoters, without stating that the scale is 0&ndash;10, that a promoter is a 9 or 10 and a detractor a 0 through 6, or that the 7s and 8s count in the denominator and nowhere else &mdash; which is the whole reason the arithmetic surprises people. CSAT and CES were the same shape: a name, a direction, and no scale, no cut point, no denominator. Every rate row now carries its scale, what counts as a hit, what sits in the denominator, and a worked example with real numbers.
- **Handle time has three answers, and the table gave one.** AHT was defined for voice only, so chat &mdash; where an agent holds several conversations at once &mdash; had no definition at all, and the two obvious ways to compute it disagree by exactly the concurrency factor. An agent in chat status for 20 minutes handling two chats that ran the full 20 minutes has an average handle time of 20 minutes per chat from the case's point of view and 10 from the agent's, and both are correct answers to different questions. - **Fixed: the worked example was painted the colour that means &ldquo;type here&rdquo;.** Every legend in the pack promises yellow is yours to fill in and green is the example; on several sheets the example was yellow, so the rows you should not have to invent looked exactly like the rows you were being asked to complete. The whole example is green now, and the example ends where the blank rows begin &mdash; the Pareto ships one billing dataset across five rows, and colouring the first green and the next four yellow said the last four were yours to make up. Getting there took three attempts and the two wrong ones are opposite errors worth recording, because a machine caught both. The first painted every yellow cell in the block whatever lay beneath it, which ran past the end of the logistic tab&rsquo;s data and turned its threshold and AUC settings into what looks like reference data. The second over-corrected to the first row alone, which split every seeded example down the middle.
- **The email and standalone exports carry the charts.** The export walked the preview&rsquo;s tables and never its charts, so a workbook whose whole point is a control chart exported as a wall of numbers. The SVG carries its own styling, so it survives being pasted anywhere; a mail client that strips inline SVG lands back where the export already was rather than breaking, and the standalone page keeps them. The closing note was stale too &mdash; it explained yellow and blue and had never learned that green now means the worked example you replace.
- **Chart labels are checked for contrast.** The visual layer asserted that text is inside the frame and not printed over another label, and never that it is readable. Text on the white plot area was never the risk &mdash; the label grey is 5.8:1 and the title 17:1. The risk is a value label sitting ON a bar, where the background is that series&rsquo; own colour: dark ink on a mid-green bar is 4.4:1, under the bar, while every structural check still passes because the text exists, sits inside the frame and overlaps nothing. Checked against WCAG AA now, with the threshold derived from each label&rsquo;s declared font rather than assumed &mdash; the first version handed the title and the value labels the 3:1 large-text allowance, which at 14px and 10.5px neither is anywhere near entitled to.
- **Fixed: a scatter whose key showed a line.** The stakeholder map plots each name as a point in an influence-against-support quadrant, and its legend drew a line swatch &mdash; which says the dots are joined. They are not, and the entire reading of that chart is which quadrant a name lands in, not any path through them.
- **Fixed: occupancy of 6000%.** The Erlang staffing curve reports a line per agent count, and for every count below the offered load it showed a service level of 0.0% beside an occupancy of 6000%, 3000%, 2000% &mdash; arithmetically load divided by agents, and meaningless, because below the offered load the queue never clears and there is no steady state to be occupied in. Service level and average speed of answer both already went blank there; occupancy alone did not. Sixty rows of it read as a broken sheet.
- **Fixed: a paragraph in a column too narrow to read it.** Notes are measured by the lines they wrap to now, not their character count, and widened across the row when there is empty space to widen into. The worst was the control plan: its six hierarchy definitions, 130&ndash;170 characters each in a column 26 wide, each wrapping six or seven lines deep so the block read as shredded text. A flat character threshold had missed all six &mdash; the same sentence is comfortable in a wide column and unreadable in a narrow one.
- **Fixed: chart labels cut mid-word, and a colour that only existed in the download.** &ldquo;Delighters &mdash; differentiatio&rdquo; reads as a broken renderer rather than a label too long for its axis; truncation now stops at a word boundary and says it happened. And the countermeasure hierarchy&rsquo;s green-amber-red durability signal, which lives in the font, was dropped by the preview renderer &mdash; so it was real in Excel and invisible on the page.
- **Fixed: a formula painted as something to type over.** Each colour has one job, and two of them are instructions &mdash; yellow says type here, green says this is the example, replace it. Both are wrong on a cell the workbook computes, and following either destroys the calculation. 55 cells across six workbooks carried one, including the Share and Rank on the Pareto&rsquo;s own worked-example row. Every colour check until now asked what a fill means for guidance, never whether it contradicts what the cell contains.
- **Fixed: blank rows counted as worked example.** Entry grids number their rows in advance and carry a formula on every row whether or not it has data, so a row holding nothing but the number 17 and a column of `IF(...,"")` looked full. That made the hypothesis log a 23-row worked example on the strength of the numbers 6 to 23, and the value stream map a 19-row one over nine real steps. A row is part of the example only if somebody typed something into it. The per-sheet legends on seven workbooks said &ldquo;Row 1 example &mdash; delete it&rdquo;, which was true of none of them.
- **A sheet that is all worked example has to say so.** The guidance check counted input cells per workbook, so a sheet could lose every one it had and the file still passed on the strength of a different tab. But &ldquo;every sheet needs a yellow cell&rdquo; turned out to be the wrong rule too: some sheets are entirely a worked example on purpose &mdash; 24 periods of control-chart data, 90 Gage R&amp;R readings, 40 handle times whose whole job is to show you a skewed distribution. What has to hold is that the sheet and its instructions agree, so an all-green sheet must be one the workbook tells you to overwrite. Three sheets said to overwrite a yellow column that no longer existed on them, and the legend said &ldquo;Green row&rdquo;, singular, and &ldquo;delete it when you start&rdquo; &mdash; which on a control chart leaves an empty chart. All of them now say the green cells are the example and the thing you replace.
- **Fixed: a row with a name and a number and nothing else.** &ldquo;DPO | 0.0507&rdquo;, and no indication of what it is or what to do about it. On the page every acronym is clickable; in a downloaded workbook nothing is. 77 rows across four workbooks &mdash; most of the Black Belt calculator pack, and the six levels of the hierarchy of controls, which the control plan charts but never defined. 73 now carry a note; the other four are verdicts and problem statements whose value is already a full sentence.
- **Fixed: three tools pointed at a template that could not do them.** &ldquo;Linear and multiple regression&rdquo;, &ldquo;Logistic regression&rdquo; and &ldquo;Multicollinearity check&rdquo; all linked to a narrative evidence pack with nowhere to write a coefficient. The build now checks that a tool&rsquo;s template mentions that tool.
- **Fixed: the certification mapping cited sections that do not exist.** Every module declares which parts of the ASQ and IASSC bodies of knowledge it covers, and nothing had ever checked those claims against the published outlines. Six of the cited ASQ sections exist in neither the 2015 nor the 2022 body of knowledge &mdash; I.C, I.D, I.E, III.E, VII.D, VIII.E &mdash; along with VI.C.5 and VII.B.5. Several more existed but meant something other than the label written beside them: &ldquo;IV.B (VOC)&rdquo; where IV.B is the business case and voice of the customer is IV.A; &ldquo;V.E (MSA)&rdquo; where V.E is probability and measurement system analysis is V.C; &ldquo;VI.D (correlation, linear/multiple regression)&rdquo; where VI.D is gap, root cause and waste analysis. The drift was systematic rather than scattered: the Define tollgate pointed at Measure sections, the DOE module at Lean methods, hypothesis testing at risk analysis. All 26 modules are re-mapped against the published outlines &mdash; and every code now carries its section title, so a reader meeting &ldquo;ASQ V.F&rdquo; is told it means process capability. The three tollgate clinics, which carried no mapping at all, have one now; that omission is what hid the drift, because any tool reading the page top to bottom paired each clinic's neighbour with the wrong module.
- **The three sections the programme did not teach, now taught.** Mapping the curriculum honestly turned up three ASQ sections with no module behind them: benchmarking, team training, and design for X. Rather than narrow the claim, they are written. M05 gains the four types of benchmarking and, more usefully, how you turn a benchmark into a defensible target &mdash; you do not copy the number, you size the gap with it and set the target from your own baseline and entitlement. M06 gains training the three audiences every project has (the team at kickoff, the process owner at handover, the front line each time a control changes), where mode of learning is a staffing decision because every hour off the phone is coverage lost. M26 gains the support translation of design for X: design for cost becomes cost-to-serve, manufacturability becomes self-service and containment, test becomes whether an agent can tell what went wrong without escalating. Coverage is 33 of 33 ASQ sections and 21 of 21 IASSC sections, and the page says so only because the build derives it from the modules.
- **A body of knowledge coverage table.** Each module stated its own mapping, but you could only ever see them one expanded module at a time, so &ldquo;full ASQ/IASSC body of knowledge&rdquo; was a claim with no way to audit it. There is now one table under Reference showing every section of both outlines against the module that teaches it, with each module a link into the module itself. It is generated from the same data the module lines are, so a section nothing covered would appear in it saying so &mdash; which is how the three gaps above were found.
- **The preview shows what the workbook actually says.** Nineteen previews were hand-written markup that the sync could only edit in place &mdash; it rewrites the cells already present, so it could correct a value but never add a row. Anything added to those workbooks afterwards was in the file you downloaded and nowhere on the page: 31 pieces of prose, including all six definitions of the hierarchy of controls and nineteen of the notes just written into the calculator pack. Every preview is now generated from its workbook, the way the newer templates always were, so the two agree by construction rather than by whoever remembered to update both &mdash; and the build fails if they ever drift.
- **The build is byte-reproducible.** An .xlsx records the time in three independent places, and every one of them was the clock, so a rebuild that changed nothing still produced twenty modified binary files and a page diff to match. `git diff` could not answer &ldquo;did that build do anything?&rdquo; &mdash; and it was hiding two things that had been true for as long as this repo has existed: a chart was re-anchored on every run, and a note&rsquo;s font rewritten on every run, growing one workbook&rsquo;s style table by an orphaned entry per build, forever. All three timestamps are pinned and both churning writes now only fire on a real change.
- **The harness grew from 147 mutants to 199, and two of them exist because a check shipped that could not fail.** The rule that says no two chart labels may print through each other passed everything on its first run, and the mutant written to break it survived: the rule was reading its own coordinates against the wrong elements. Chasing it, the second mutant turned out to be invalid too &mdash; a label slid into empty space collides with nothing. Both the bug and the bad mutant that hid it are written up in the code, because &ldquo;the mutant was wrong&rdquo; is the more dangerous conclusion: it is the one that talks you out of a real finding.

## New in v3.1 — the charts stopped contradicting their own sheets

- **Every control chart now marks its own signals.** Ten charts, and not one of them showed which point was out of control — the most standard element of a control chart, absent from all of them. Points outside the limits are flagged red; eight in a row on one side is flagged amber. Deliberately only those two rules: the full Nelson set across ten charts drives the false-alarm rate to roughly one signal per chart per fortnight on a perfectly stable process, which is exactly the tampering the workbook warns against. Two of the ten needed different maths — gaps between rare events are exponential and opportunities-between-events are geometric, so P(above the mean) is about 0.368 rather than 0.5, and a naive run rule there advertises odds it does not deliver. The t-chart runs its rule on the transformed scale and the g-chart runs it against the median.
- **Fixed: a Pareto that was not sorted.** Its cumulative was a running sum down the rows, so it was only a Pareto if you happened to type your categories in descending order. The shipped example did — which is why it looked right and passed every check. Type them in any order now and the ranked block sorts itself.
- **Fixed: three more charts that claimed a ranking and sorted nothing** — the X-Y matrix (titled &ldquo;the tall bars are where to look&rdquo;), the solution selection matrix, and the FMEA, whose entire method is to work the highest RPN first.
- **Fixed: Kano gave the opposite advice on the two most common answers.** Two cells of the published evaluation table were transposed. It also counted four classes while its classifier returns six, so a feature classified Reverse was computed and counted nowhere.
- **Fixed: reference lines that contradicted the sheet they sat on.** The FMEA drew its action line at RPN 100 while its own summary counted &ldquo;above 200, act now&rdquo;. The hypothesis log hardcoded alpha at 0.05 while the sheet has a validated alpha input, and keyed the line on the p-value column so the standard vanished across four fifths of the axis.
- **Fixed: the t-chart's centre line sat outside the middle of its own limits**, and the g-chart computed a UCL that nothing ever plotted.
- **Fixed: lower-case jargon was never clickable.** The matcher is case-sensitive by necessity — a case-insensitive one would let IT, OR, US and AND match everywhere in prose. But ordinary-word terms are usually written lower-case mid-sentence, and none of them matched: &ldquo;gemba&rdquo; appears more often in this document than &ldquo;Gemba&rdquo; did. 856 explainer links became 1,315.
- **Explainers explain.** Terms inside an explainer are now clickable, with a back trail to walk out, and pointer and keyboard follow the same path — Enter used to navigate without recording the trail, so the back button never appeared for keyboard users.
- **A published quality bar for charts.** CHART-QA.md and `tools/chart_rubric.py`: three gates and three scores, with the ceiling question being &ldquo;would you rather use this than spend two minutes making your own?&rdquo; The first honest run scored 3 of 33. All 33 clear it now.

## In v2.4 — four more ways a support project makes money

- **Deflect to self-service or a cheaper channel.** The contact still happens, it just does not need a person. The benefit is the cost *difference*, never the whole contact cost — a distinction the old “eliminate a contact driver” model could not express.
- **Reduce agent attrition.** Recruiting, onboarding, training and the ramp you pay for twice. At 30–45% annual attrition this is often the largest number in a support P&L, and it is the only model here priced per person rather than per contact.
- **Cut the cost of poor quality.** Credits, refunds, goodwill and SLA penalties. Priced per incident, so a small defect-rate move can dwarf a big handle-time project — and the money is already in Finance's ledger, so you are not asking them to believe a model.
- **Protect revenue at risk.** The only revenue model rather than cost. Priced per customer, not per contact, because one customer raises several tickets — and the wizard now asks for customers so you cannot accidentally multiply the benefit by your contacts-per-customer ratio.
